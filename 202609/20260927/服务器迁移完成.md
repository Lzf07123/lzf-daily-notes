# 服务器迁移完成

## Context

服务器迁移完成，广州主服务器需要将系统迁移为rocky，需要在重装完成后重新部署博客等服务，为了让服务更加安全，将使用firewall进行端口暴露的控制

---

## Key Takeaway

- 彻底关闭kdump内核转储释放200M内存空间
- 修改firewall防火墙默认区域
- 使用nmcli控制接口所属防火墙区域
- 关闭docker控制iptables的自动管理
- 使用一个公共网络区域使得nginx发现其他服务

---

## Pratice

- 在rhel系列系统上可以在安装系统时就关闭kdump，后续想要进行关闭可以使用`grubby`的相关命令删除kdump配置、删除`/etc/default/grub`配置文件关于crashkernel相关配置段、最后使用`grub2-mkconfig`重建引导文件并关闭kdump的开机自启，从而关闭kdump并释放内存空间
- 使用`firewall-cmd --set-default-zone=ZONE`命令修改firewall默认空间
- 向`/etc/docker/daemon.json`文件内添加`"iptables": false`关闭docker对iptables防火墙的控制
- 使用`docker network create NETWORK`创建一个网络（该网络不会被prune清除），用于nginx发现服务，可在compose文件内为服务定义aliases别名方便发现服务
- 将`StrictForwardPorts`配置为`yes`禁止docker隐式放行端口
- 由于关闭了docker对iptables的控制，所以`-p`参数与compose文件内的`ports`字段都将自动失效，不会自动插入iptables规则，需要使用firewall手动控制端口转发，使用`firewall-cmd --permanent --zone= --add-forward-port=`命令控制端口转发或直接使用已配置的nginx进行开放服务
